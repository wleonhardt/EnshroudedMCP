# 0050: Direct saved-profile join needs a supported client lifecycle API

Date: 2026-11-16. Status: requested upstream as [#1144](https://github.com/enshwick/enshwick/issues/1144); no executor or native acceptance.

The user requested direct server join using saved credentials and settings, then explicitly authorized posting the prepared API request. Make this priority 1. Proposed client_join(profile, operation) is a future interface, not an available tool.

Inspected published main 43aa478bb9de4d97824543a0a2e2d2dd58a79f81 still exposes only in-world screen/tab/look/move/recipe-highlight CommandAction variants. Its loader already intercepts game-driven joins for mod compatibility. That hook receives a borrowed provider/target during the game's own call; the target reader deliberately copies only the non-secret prefix before the password. It supplies neither an owned saved-profile/credential request nor a public initiating API. A routed function name is not a safe executor, and copying the prefix does not create a valid credential-bearing target.

Sources: [client commands](https://github.com/enshwick/enshwick/blob/43aa478bb9de4d97824543a0a2e2d2dd58a79f81/crates/internal/actions/src/input/commands.rs), [join hook](https://github.com/enshwick/enshwick/blob/43aa478bb9de4d97824543a0a2e2d2dd58a79f81/crates/runtime/loader/src/base/join/runtime.rs), [target boundary](https://github.com/enshwick/enshwick/blob/43aa478bb9de4d97824543a0a2e2d2dd58a79f81/crates/runtime/loader/src/base/join/target.rs).

The MCP should submit only a local allowlisted profile label and caller operation identity. The client resolves the server, supported character/settings selection and privately authorized credential reference. Prefer the game's saved-profile path if exposed. Do not create a plaintext password config or expose secrets in tool arguments, previews, receipts, journals or probes. Steam retains its normal authentication; no DRM change is involved. Credential storage is not implemented or selected before the provider contract is known.

Join happens before a world session exists. Keep the current fresh nonzero-session guards for in-game commands. A new lifecycle route needs an observed fresh menu/connection-context generation, bound to boot, profile/settings version, target and character selection. Refuse already connected/connecting clients; do not leave another world implicitly. Recheck before one client-phase dispatch and preserve durable once-only identities. A timeout is not cancellation or permission to retry.

A read-only connection outcome should distinguish provider-supported queue/connection/authentication/loading/connected/refused/cancelled/unknown states and redacted failures. The intended peer must match the configured profile: InGame alone proves no target, and the joined scene/world-key getter may be unavailable. Correlate the managed server roster independently where possible without treating client entity IDs as server selectors. Credential refusal and unknown completion never trigger an automatic new join.

Acceptance needs a deliberately configured isolated profile, successful intended-peer join from Menu, current client session and independent roster agreement, supported failures, stale-profile/context refusal, duplicates/in-flight conflicts and cancellation uncertainty. Verify secret-free evidence and clean leave through a supported route. Native logout remains separate until an executor exists. No secret file or credential store was read during this design.

The upstream request is separate from #1107's in-world controls and adds no speculative MCP stub, SDK patch, game offsets or arbitrary event injection. Official non-SDK direct-connect support remains unqualified; browser research could not proceed because BrowserOS neo tools were unavailable. Do not assume a Steam URI, console command or command-line password flag works for this game. SDK/provider support must be qualified before implementation or migration. Installed 0.42.0/0.20.1 and SDK 6a151a95 / ABI 12.1 remain unchanged by this request.
