# 0106: Qualify held launcher facts and full-precision process handoff checks

Date: 2026-11-17. Status: optional Windows source/process fixture qualified; no game trial or native lifecycle acceptance.

Decision 0104 stops a real Menu trial when the private handoff checker compares CIM datetime with a full-precision Win32 creation value. It also loses the initial launcher's exit code after the short-lived launcher script releases its process object. Keep that review consumed. Prepare a corrected, independently testable process witness before another runtime exception; do not relaunch the game or infer a successful native phase from the earlier cleanup.

Fresh owned-process probes identify a second boundary. After exit, GetProcessTimes can still report creation time while QueryFullProcessImageNameW refuses the image query, including when the original CreateProcess handle remains held. Preserve those failed image probes. The new optional qualification/process-handoff helper therefore separates requested executable, independently observed executable, creation time, live/exited state and actual exit code. Missing exited image stays null. A live image query failure or observed path mismatch refuses; a requested path never becomes an observed one.

Borrow the exact CreateProcess handle retained by the caller's own Popen object. Do not close it or reselect the launcher by PID after exit. This is specifically qualified with the installed Windows CPython 3.15 implementation, whose Popen keeps that handle. GetProcessTimes supplies raw FILETIME precision. WaitForSingleObject distinguishes actual exit before GetExitCodeProcess is interpreted, including a real exit code of 259. The existing strict scripts/process_exit live observer and all its callers stay unchanged. The helper launches and stops nothing and exposes no MCP tool.

The direct branch requires matching live PID, creation and executable. The handoff branch requires initial exit 0; matching preexisting parent PID, exact full-precision creation and expected image before/after; a distinct child with expected image in the bounded creation interval; and independently observed parent linkage. CIM contributes only PID, parent PID and executable path. A one-tick change between Win32 parent identities still refuses: do not add a tolerance to hide the original mixed-representation defect. A separate listener guard requires one loopback binding with the expected port and child owner.

The actual fixture starts only owned Python processes. One launcher writes its request into an already running owned parent's input; that parent starts one child. The initial launcher object remains retained through exit and fact collection. The child opens a disposable loopback listener. Full-precision identities, CIM linkage and kernel listener ownership are independently observed. All owned processes exit normally after input closure, with bounded waits; failure cleanup can terminate only the fixture's own Python handles. No arbitrary game process is selected. A direct live child and exited children with actual codes 0, 7 and 259 are qualified separately.

Six optional test methods pass. An extra lossy/unrelated CIM timestamp cannot replace the Win32 facts. Unknown exited-image status remains explicit.
