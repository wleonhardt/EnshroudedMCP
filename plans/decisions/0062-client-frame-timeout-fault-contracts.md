# 0062: Exercise client timeout boundaries through the registered frame handler

Date: 2026-11-16. Status: source contracts qualified; live interruption acceptance open.

The existing unanswered-request test proved queue cleanup, and the policy atomic-state test proved begin/cancel exclusion. Neither exercised a real write held before begin and delivered to a late production frame, nor reply loss after the registered frame dispatched a native command. Add two test-only SDK fake-host fixtures covering these boundaries without changing production code or deadlines.

The first fixture obtains a real command preview with a fresh copied session, creates an isolated write flag, and starts the actual client tool call on a worker. It detaches the queued request before begin and waits for the actual two-second listener timeout. It then republishes that held job to the registered production frame handler. The cancelled token prevents dispatch: two late frames produce zero native commands, no durable reservation, no journal and no retained operation. Only the fixture write flag exists. This controlled handoff models a frame delayed between dequeue and begin; it does not stall the live game.

The second fixture replaces only the reply channel of a queued real command. The registered production frame handler submits exactly one native command; its reply is withheld until the actual listener timeout reports started/outcome unknown. Delivery to the expired receiver fails. An explicit same-identity replay through the real tool call and frame handler retains the pending native outcome, exactly one native command, exactly one durable identity and byte-identical reservation/journal. Poll-age metadata may advance and is not confused with a new outcome. Arrival and rendered proof flags remain false. This is controlled reply loss, not a claim of native disconnect or an automatic runtime retry policy.

Fixture setup starts copied-snapshot sampling before injecting fresh context, checks real preview/admission, and uses an exclusive canonical direct-child directory for bounded cleanup. Tests coordinate on queue publication rather than arbitrary sleeps. They deliberately retain the actual production two-second wait. No runtime dependency, package version, installed DLL, provider, write gate, session guard or deadline changes.

Both targeted tests pass. The complete private/public product suites pass 372 Rust executions and 71 Python tests, strict Clippy, formatting and both release builds. The inactive historical ABI 12.8 candidate remains separately qualified at 370 Rust executions; these new fixtures are not retroactively claimed as part of that candidate. Actual native callback stalls, pending command cancellation/disconnect, storage append/sync faults and independent rendered/persistence effects remain open.
