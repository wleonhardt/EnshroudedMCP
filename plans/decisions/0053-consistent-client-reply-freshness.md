# 0053: Return polling freshness with every retained client command outcome

Date: 2026-11-16. Status: installed with native read-only/prior-boot regression; native current-boot acceptance open.

Status and command inventory already compute observation age, but command submission/replay and cancellation replies omitted it. A retained native age alone does not tell the caller whether the frame has polled recently. Extend the existing policy formatter to all outcome reply paths, without introducing new status semantics or a new executor.

Companion 0.20.2 source adds status_observation to command submission and same-identity replay replies, cancellation submission/replay replies, and dry cancellation's last_outcome. They use the same monotonic last-frame-poll age, stale boundary, polling-finished state and current_context_verified:false as status/inventory. Never-polled replies have null age and are stale. Reading a retained outcome does not poll the SDK, refresh its timestamp, dispatch again or append a journal row. Cancellation acceptance remains separate from the previously observed native command state. Dynamic freshness stays outside durable outcomes and journals. Matched 0.43.0/0.20.2 is installed and passes native read-only/prior-boot regression; joined/current-boot reply acceptance remains unverified.

Keep the stored result separate from the response. One Entry::outcome formatter clones it and adds policy::client_control::status_observation from the unchanged last-poll Instant and terminal flag. Status/inventory, submission, replay, cancellation and dry cancellation's nested outcome all share that formatter. Journals still serialize the stored result, not dynamic elapsed time. Preserve write admission, preview, deadline, once-only identity and cancellation gates.

The new regression first failed because the submission reply had no status_observation. It now covers never-polled submission, two-second stalled pending replay, dry cancellation, first and repeated real cancellation, and aged terminal replay/cancellation. Retained reads preserve journal bytes and submit only the original native command. Existing terminal/error regressions compare durable outcomes separately from elapsed response metadata. The policy's existing 1,000/1,001 ms boundary tests remain authoritative.

Private/public checks pass 366 Rust test executions, 71 Python tests, strict Clippy, formatting and both release builds. Before deployment, installed 0.43.0/0.20.1 read-only preflight passed 32 server and 13 client probes, 18 prior-boot identities, empty roster, fresh Menu, complete world baselines, twelve hashes, immutable ledgers and absent flags. There are no current-boot command identities. Those preflight checks qualified only the previous installed baseline, not the new response paths. Do not create input merely to claim coverage. Qualify the candidate with supported joined current-boot submission/replay/cancellation before asserting native reply behavior.
