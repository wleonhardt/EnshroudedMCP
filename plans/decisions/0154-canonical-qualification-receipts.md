# 0154: Correlate qualification receipts before controller actions

Date: 2026-11-20. Status: source helper and read-only historical replay qualified; no native action.

Decision0153 exposes two copied-controller assumptions: publication initially selects an old cohort candidate receipt, and a post-stop verifier expects server_shutdown instead of the producer's server_shutdown_intent kind. Both refuse rather than accepting false evidence, but the mistakes are detected late. Add a small shared read-only helper before another controller generation is frozen.

`scripts/qualification_receipts.py` reads only candidate-provenance.json under the caller's cohort directory. Require an independently supplied exact source commit and artifact-name/version map from the frozen plan or compiler profile. Refuse a different source even when package versions match, missing or extra artifact names, wrong versions, and malformed positive sizes, SHA-256 values or paths. Bound the receipt read to64 KiB and emit stable reasons without paths or receipt contents. Artifact paths remain unopened metadata; signatures, file hashes, source closure and installed identity still need their existing independent checks. A receipt is not installation or launch permission.

The shutdown verifier accepts an already-read owned record and exact expected operation/session. Require the exact three-field server_shutdown_intent object. Do not reconstruct execution authority, infer process exit or assert final-save causality. A shared synthetic JSON fixture is compared with the actual Rust shutdown producer in the existing once-only/replay test and accepted by the Python verifier. This checks format correspondence across languages without changing runtime behavior or importing deployment code into the mod.

A missing-helper reproduction fails before implementation. Seven Python cases cover current and distinct stale cohorts with identical versions, exact artifact sets and versions, invalid records/expectations, bounded redacted failures, shared typed intent format, extra/missing fields and wrong operation/session. The actual Rust producer comparison passes. Read-only replay against frozen historical qualification data accepts the paired current receipt and native intent, refuses the earlier cohort receipt and leaves intent bytes unchanged. This is metadata correlation, not a new native qualification run.

Future controllers must include this helper in their frozen source closure and pass independent expectations before replacement/launch. Consumed controllers remain immutable. Existing process, package, provider, opaque configuration, once-only identity, write gates and shutdown/exit checks remain required. No installed file, game process, provider, configuration, credential, save or runtime log is changed/read by this increment. Native positive player buff data, effects/rendering and in-flight interruption acceptance remain open.

Final verification passes455 Rust/117 Python, strict Clippy, formatting, both release builds and offline contracts. All other crate files and the changed module before cfg(test) remain byte-identical to the previous source checkpoint. No runtime source or version change is made.
