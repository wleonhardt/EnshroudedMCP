# 0057: Read retained shutdown status without an active world

Date: 2026-11-16. Status: source qualified; native installation and acceptance pending.

A scheduled shutdown fixture returned explicit outcome uncertainty after execution began. Its immediate-receipt assertion failed even though a retained record could be available afterward. Existing dry shutdown lookup also requires an active world, so it refuses after the published ShutdownStarted event invalidates that world. Neither uncertainty nor an unavailable world should cause another native stop request.

Server 0.45.0 adds server_shutdown_status with only the original operation identity. It reads copied operation metadata without World access, a scheduler, active world, write flag or native executor. This is a control-record read, not a game read. All native requests and lifecycle updates retain their existing game-thread execution. No command, reservation, journal append, restart or retry is introduced.

The response separates a retained native_outcome from conservative top-level proof fields. Native acceptance and lifecycle observations remain historical, not proof of the current world, process exit, causal final save or persisted content. Current-world verification, identity reconstruction, automatic retry/restart and process/save proof remain false. No timeout is widened.

The listener uses try_lock. A busy store returns state busy with null native_outcome; it does not assert that the identity exists or that its command started. An available retained record returns state retained. An absent record with an existing marker returns prior_boot_unavailable with null native_outcome, without decoding or reconstructing the marker. Other identities refuse. Copy the record or inspect marker presence under the same state lock, preventing concurrent reservation from being mislabeled as prior-boot data. No historical record is promoted into current-world authority. Transport availability after shutdown is not guaranteed.

Strict game-free admission rejects paths, uppercase identities, overlong identities and any extra selectors. Policy regression is initially red because the status admission API is absent. The adapter fixture covers a busy store, unknown identity, listener-thread reads without ticking, removed write flag, lifecycle updates after world invalidation, historical records after a new world and undecodable prior reservations. It preserves native stop and audit assertions. An exact shutdown-started uncertainty response can reconcile the same retained record; every other error still fails. The original grant fixture failure remains unexplained.

Full Rust suites use RUST_TEST_THREADS=1; no production deadline changes. Three fixed refusal probes are added, for 38 checks across 36 advertised tools.
