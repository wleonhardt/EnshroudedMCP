# Construction phases

Keep the full administrative workshop objective in goal.md. Native client control has first priority; supported independent work may proceed while an upstream API is missing.

| Phase | Work | Gate |
| --- | --- | --- |
| 1 | Native menu/option selection, join/leave, bounded movement/look and rendered capture | Repeatable login, observation, positioning and logout with verified outcomes |
| 2 | Healthy quiet site, tiny foundation pier, two rendered seam views, full capture, undo and reload | Visible contact and exact recovery; native preview alone is insufficient |
| 3 | Uneven terrain, brick boundaries, material adjacency, placement order, openings and gap filling | Repeatable rendered results with complete read-back/recovery per case |
| 4 | Bounded foundations, alignment and workshop module composition | Small structure fits site, persists while placed and recovers correctly |
| 5 | Supported station/prop lifecycle and recipe requirement observations | Compact workshop is visibly usable; no survival-cost claim |
| 6 | Reusable advanced modules and bounded resumable jobs | Advanced workshop spawns, survives restart and demonstrates partial-failure recovery |

Every experiment requires an independent oracle, relevant tests, isolated-site review, existing write gates and durable journals, rendered and exact read-back evidence, applicable undo/reload checks, explicit research-setting restoration and logout before unrelated development. Unknown outcomes must be reconciled rather than resent. Desktop control is last resort and each use records a prioritized native gap. No phase is accepted by transport probes or source tests alone.
